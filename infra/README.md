# infra

Pulumi owns the cloud resources, Ansible owns everything inside the box. Neither runs in `ci` — they
touch a real cloud account — but deploying is a workflow, not a laptop ritual.

## Layout

```text
__main__.py             wires the modules and exports the stack outputs
resources/
  host.py               the Host dataclass every compute module returns
  compute_oci.py        the box
  passwords.py          generated Postgres and restic passwords
  storage_b2.py         B2 bucket and its scoped application key
  tailnet.py            the Tailscale policy
  telemetry_logfire.py  Logfire project, write token, alerts
  limits_oci.py         the spend fence: quota policy and budget
  monitoring_healthchecks.py  the checks the box and the alerts ping
logfire/dashboards/     dashboard JSON exported from the Logfire UI
sdks/                   generated SDKs for the two Terraform-bridged providers
Pulumi.prod.yaml        committed; secrets are `secure:` ciphertext
ansible/
  inventory.ini         committed; a tailnet name is not a secret
  group_vars/old_news/  non-secret settings only
  roles/
    tailscale/          apt install, and the tag that stops the node key expiring
    bootstrap/          docker
    app/                compose file, .env, systemd unit, readiness gate
    backup/             restic -> B2 on a daily timer
    otel/               reports what the systemd timers did
    heartbeat/          dead-man ping, gated on /health/ready
    keepbusy/           daily CPU burn to defeat Oracle's idle sweep
```

Vendor-suffixed modules are the replaceable ones: swapping cloud is a new
`resources/compute_hetzner.py` returning a `Host`, and one changed import.

## How a deploy happens

Push to `main` → `ci` tests and pushes three `linux/arm64` images tagged with the commit sha →
`deploy` runs the playbook with `image_tag=<sha>`.

Never `latest`, so the box's state is a function of a commit rather than of when it last pulled.
`just deploy <sha>` is the recipe CI runs, so manual and automatic deploys cannot drift.

The box holds no GitHub credential and no clone of this repo. Ansible copies the one file it needs,
`compose.yaml`, from the control node.

## One source of truth

Every secret is generated by Pulumi or held as encrypted stack config. Ansible reads them from
`pulumi stack output --json --show-secrets` and stores none of them.

| Value                         | Where it comes from                      |
| ----------------------------- | ---------------------------------------- |
| Postgres and restic passwords | `random.RandomPassword`                  |
| B2 bucket and application key | `b2.Bucket` + `b2.ApplicationKey`        |
| Logfire write token           | `logfire.Project` + `logfire.WriteToken` |
| Tailscale policy and auth key | `tailscale.Acl` + `tailscale.TailnetKey` |
| healthchecks.io heartbeat URL | `healthchecksio.Check` → its `ping_url`  |
| Logfire alerts and channel    | `logfire.Alert` + `logfire.Channel`      |
| OCI quota policy and budget   | `limits.Quota` + `budget.Budget`         |
| Logfire alert webhook         | `healthchecksio.Check` → its `/fail` URL |

Irreducible is provider auth: each provider needs one root credential, since you cannot bootstrap
trust from inside the thing being bootstrapped.

```sh
cd infra
pulumi stack select prod
pulumi config set --secret healthchecksio:apiKey ...
pulumi config set --secret b2:applicationKeyId ...
pulumi config set --secret b2:applicationKey ...
pulumi config set --secret logfire:apiKey ...
pulumi config set --secret tailscale:apiKey ...
pulumi config set tailscale:tailnet tailed73bc.ts.net
```

Tailscale takes an API access key, not an OAuth client: a client must name a tag it may act as, and
`tag:ci` does not exist until this program has written the policy. If Logfire cannot infer its API
base URL, set `logfire:baseUrl` explicitly.

Three secrets live in the repository: `PULUMI_ACCESS_TOKEN`, `TS_OAUTH_CLIENT_ID`,
`TS_OAUTH_SECRET`. The Tailscale client is hand-made deliberately — it is what lets CI reach
anything, so it cannot come from a stack CI can only read once connected.

A deploy needs no cloud credentials; `stack output` talks to Pulumi Cloud alone. Only `infra-up` and
`infra-drift` touch OCI, B2, Logfire and Tailscale.

## Who applies what

Both pipelines are jobs in `ci.yml`, and they are ordered:

| Job      | Does                                  | Runs on                       |
| -------- | ------------------------------------- | ----------------------------- |
| `infra`  | `pulumi preview`, then `up` on `main` | every push and pull request   |
| `deploy` | the Ansible playbook                  | `main`, `needs: [..., infra]` |

`needs: infra` is the ordering. The playbook's variables are this stack's outputs, and outputs are
written only when an update finishes — a deploy racing an update reads the previous ones and
configures the box with them.

GitHub holds `PULUMI_ACCESS_TOKEN`, which decrypts the stack and was already needed for
`stack output`. `oci:privateKey`, `b2:applicationKey`, `logfire:apiKey`, `tailscale:apiKey` and
`healthchecksio:apiKey` live in stack config and reach the providers through the CLI.

The pull request is the gate: `preview` on the PR, `up` on merge. `preview` on every push is also
what catches drift between `infra-drift` runs. Protect `main` so a direct push cannot skip it.

## The easy maintenance path

Everything routine should be doable from a browser and nothing else — no CLI, no SSH key, no
credential on disk. That rules the borrowed laptop and the phone in equally, and it is the reason
the two pipelines above are triggered by git rather than by a person running a command.

What a browser alone can do:

- **Change anything in `infra/`** — edit in the GitHub web UI, open a PR, read Pulumi's preview
  comment, merge. Dashboards, alerts, quota, ACL, the lot.
- **Change the app** — same, `ci` then `deploy` run themselves.
- **Redeploy a known-good sha** — `deploy.yml` has a `workflow_dispatch` with a sha input.
- **Rotate a secret** — stack config, including `secure:` values, is editable in the Pulumi Cloud
  UI.
- **Retag or re-authorise the box** — the Tailscale admin console, which interrupts nothing.
- **See what is wrong** — Logfire, and healthchecks.io for the dead-man.

What still needs a trusted machine, in rough order of how much it would hurt:

1. **A restore.** `just backup-verify` proves the archive weekly and now reports its result, so you
   would _know_. Acting on a bad one needs a shell.
2. **Anything needing SSH into the box** that a playbook run cannot fix. The OCI serial console is
   browser-reachable but is a last resort, not a maintenance tool.
3. **`pulumi import`.** Adopting a resource is CLI-only, so adopt before you need it, not after.
4. **`just infra-drift`.** Out-of-band drift is invisible until the next PR preview shows it.
   Scheduled drift detection is above Pulumi's free tier, and doing it in GitHub Actions would mean
   putting an OCI credential there — which is the thing this split exists to avoid.

The standing cost of this is that **no laptop may be load-bearing**. Anything that only works
because of a file in your home directory is a hole in it — see the OCI credential below.

### The OCI credential

Every other provider's root credential is already stack config, encrypted in Pulumi Cloud. OCI is
the exception: `oci:configFileProfile: DEFAULT` reads `~/.oci/config`, so the program only runs on a
machine that has it. A runner has no home directory of yours, and neither does a borrowed laptop.

Move it into the stack, from the machine that still has the key:

```sh
pulumi config set oci:tenancyOcid "$(git config --get oci.tenancy || echo ocid1.tenancy...)"
pulumi config set oci:userOcid ocid1.user...
pulumi config set --secret oci:fingerprint aa:bb:cc:...
pulumi config set --secret oci:privateKey < ~/.oci/oci_api_key.pem
pulumi config rm oci:configFileProfile
just infra-preview   # must still refresh OCI without an auth error
```

`infra-drift` is the wrong check here — it asserts _no_ changes, and there are resources still to
create. It becomes the acceptance test again after the first `infra-up`.

Do not reuse your own OCI user for this. Create one whose IAM policy allows what this stack manages
and denies instance deletion — the stack is then unable to destroy the box it cannot rebuild, which
is worth more here than it would be anywhere with spare capacity.

### Tailnet ACL

The policy lives in `tailnet.py` rather than the admin console, so it arrives as a reviewable diff.
`tagOwners` says who may _assign_ a tag; `grants` and `ssh` are the traffic rules. CI gets `accept`
because `check` needs a browser no runner has.

**`pulumi up` overwrites the whole policy**, so the program must carry every rule the tailnet needs,
including the ones already there. `reset_acl_on_destroy` is off: the default policy has no
`tagOwners`, which would invalidate the box's tag.

**A tagged device is owned by the tag, not by you**, so an `ssh` rule targeting `autogroup:self`
stops matching the box once it is tagged. Tagging without an explicit `tag:server` rule silently
costs you access.

### Reaching it

Tailscale Serve publishes the API at `https://rss-01.<tailnet>.ts.net`, so the app binds `127.0.0.1`
and nothing listens on the tailnet directly. That buys a real Let's Encrypt certificate with no DNS
records, no open ports and no renewal to forget, and keeps any hostname out of the app's config.

It needs `httpsEnabled` on the tailnet, which `tailnet.py` sets. Making it public later is
`tailscale funnel` plus a `nodeAttrs` entry — still no DNS.

### Tag the box, or lose it

An untagged node's key expires — this one would have on 2027-02-09 — and the box then leaves the
tailnet, with no public SSH to fall back on.

Defining a tag and assigning one differ. `pulumi up` writes `tagOwners`, making `tag:server` exist;
the device is then given the tag in the console (Machines → Edit ACL tags) or over the API.
`keyExpiryDisabled` is set explicitly too rather than resting on tagged devices implicitly not
expiring.

`just retag` does it over SSH, but re-authenticating kills the connection it runs over, so expect
one failed play. The console and API do not interrupt anything.

The playbook asserts the tag every run rather than quietly converging a box on a countdown.

## Adopting the box

The box was launched by hand, so Pulumi was taught about it:

```sh
pulumi import oci:Core/vcn:Vcn vcn <vcn-ocid>
pulumi import oci:Core/internetGateway:InternetGateway internet-gateway <igw-ocid>
pulumi import oci:Core/defaultRouteTable:DefaultRouteTable default-route-table <rt-ocid>
pulumi import oci:Core/defaultSecurityList:DefaultSecurityList default-security-list <sl-ocid>
pulumi import oci:Core/subnet:Subnet subnet <subnet-ocid>
pulumi import oci:Core/instance:Instance instance <instance-ocid>
```

Import before the first `up`, or it tries to create a second instance against exhausted quota. A
hand-made B2 bucket needs `pulumi import b2:index/bucket:Bucket backups <bucket-id>` too.

**The acceptance test is `just infra-drift` reporting no changes.** Two things keep it that way: the
image OCID is pinned rather than resolved as "newest Ubuntu", since a changed `source_details`
replaces the instance, and the instance carries `protect=True`.

The VCN's **default** route table and security list are adopted rather than replaced — that is what
the subnet is attached to.

## The spend fence

`limits_oci.py` holds a quota policy and a budget. They are not the same tool: the quota **denies**
resource creation at the API, the budget only emails you a day or so later. The quota is what
actually stops a stray `up` buying a second box; the budget is the backstop for the families a quota
does not cover.

Both already existed in the console, so every value in the module matches what is live and both are
adopted:

```sh
pulumi import oci:Limits/quota:Quota free-tier-cap \
  ocid1.quota.oc1..aaaaaaaa5hmlgalfuy54irece67vptjh2rsykp35cp7yu4ohuufwcghmvvbq
pulumi import oci:Budget/budget:Budget free-tier-guard \
  ocid1.budget.oc1.ap-sydney-1.amaaaaaanuq6c4iaw4exgi56ceih6piqzaezlrtotx3ybvoklxlxdnqiimrq
pulumi import oci:Budget/rule:Rule any-spend \
  budgets/ocid1.budget.oc1.ap-sydney-1.amaaaaaanuq6c4iaw4exgi56ceih6piqzaezlrtotx3ybvoklxlxdnqiimrq/alertRules/ocid1.alertrule.oc1.ap-sydney-1.amaaaaaanuq6c4iabip6ro56arhb6di6qlizp27vbyvwkzlvsmdgd3h6udeq
```

`budgetAlertRecipient` must be set before the first `up` or the rule diffs on its recipient.

The statement keyword is **`quota`, singular** —
`set compute-core quota standard-a1-core-count to 2 in tenancy`. The plural `quotas` is a different
statement shape and does not mean the same thing. `oci limits quota get --quota-id <ocid>` prints
what is live; `oci limits service list` prints the families.

**The quota only caps three families.** Nothing currently stops an Autonomous Database, a load
balancer or a file system being created — each is Always Free up to a point and billable past it.
Adding `zero database quotas in tenancy` and friends would close that, at the cost of a real diff
against a fence that is deliberate. Leave `vcn` alone whatever you do: the VCN, gateway and subnet
in `compute_oci.py` are quota-governed too.

The acceptance test is the same one the box gets: `just infra-drift` reporting no changes.

## Observability

Three things report, and they cover different blind spots:

| What                                  | How                                                   |
| ------------------------------------- | ----------------------------------------------------- |
| App, worker, queue and Postgres spans | `logfire` in-process, `OLD_NEWS_TELEMETRY__*`         |
| Host, container and Postgres metrics  | `otel-collector` compose service, `telemetry` profile |
| What the systemd timers did           | `roles/otel`, `ExecStopPost` on each unit             |

The API and the worker report **different service names** (`old-news-api`, `old-news-worker`). One
name for both collapses them into a single stream and makes the service filter useless.

Queue spans carry OpenTelemetry's `messaging.*` attributes, which is what makes Logfire read them as
a queue rather than as ordinary spans with a job id. `defer` opens a send span so a poll and the
schedule that deferred it share one trace.

Alerts live in `telemetry_logfire.py` for the same reason the tailnet ACL does. Dashboards do not:
the provider takes an opaque blob, so those are **exported from the UI** into `logfire/dashboards/`
and committed. Adding one is export, drop in, `just infra-up`.

Nothing is created until `logfireAlertWebhook` is set — an alert with no channel silently does
nothing. Point it at a **separate** healthchecks.io check's `/fail` URL, not `heartbeatUrl`: that
one means "the box is alive", and an application alert tripping it would say the wrong thing.

The collector mounts the docker socket, which is root on the host. It is read-only and it is the
only container that gets one. `otel_collector_enabled: false` drops the container and the mount
together.

## Reclamation

Oracle reclaims Always Free compute idle on CPU, network _and_ memory over 7 days; breaking one is
enough. `keepbusy` burns one core at 50% for two hours a day. Oracle has removed its guidance that
Pay As You Go exempts you, so this stays until measured otherwise — once Postgres is running,
`shared_buffers` may clear the bar on its own.

## Before you trust any of this

**Perform one real restore.** An untested backup is a hypothesis.

```sh
restic snapshots
restic dump latest old-news.sql.gz | gunzip | pg_restore -d old_news
```

`just backup-verify` runs the same path end to end, and a timer runs it on the box.

## Prerequisites

- The Pulumi CLI: `brew install pulumi`, or the installer at `get.pulumi.com`. Both read the same
  `~/.pulumi`, so don't run both.
- A `$1` budget alert in the OCI console before provisioning anything. `limits_oci.py` adopts it
  afterwards — the fence has to exist before there is a stack to fence.
